## What I verified in the committed bytes

**Dependency boundary (ac-0004).** `crates/loader-git/Cargo.toml` declares `unisphere-core` plus `libc` under `cfg(unix)`; `crates/adapter-git-ai/Cargo.toml` declares `unisphere-core`, `serde`, `serde_json`. `git diff base..candidate -- Cargo.lock` adds exactly two package entries, both the new local crates — no `git2`, no `gix`, no git-ai crate, no HTTP or daemon client. `unisphere-arch-check.rs` gained matching allow-list rows (`unisphere-loader-git` → core|libc, `unisphere-adapter-git-ai` → core|serde|serde_json) and both names in the workspace package allow-list, so the sensor enforces the boundary rather than trusting it. Because the adapter is named `unisphere-adapter-*`, its production source is also swept by the existing purity sensor for `std::{fs,env,process,net,thread}`, clocks and file includes — and it contains none.

**F1 seam, as approved.** `crates/cli/src/git_notes.rs` parses fully before calling `make_collector`, so `--help` and invalid syntax never need Git or a backend; `--git-executable` must be absolute (checked in the CLI and again in the loader's `command()`); the app owns resolution in `resolve_git()` (`crates/app/src/adapters.rs`), which canonicalizes, requires a regular file with an execute bit, and treats an absent or empty `PATH` as `GitUnavailable`. The proof exercises all three states: sealed empty `PATH` plus explicit real Git for the positive run, a non-existent `--git-executable`, and no flag under empty `PATH`, the latter two asserted as `git_unavailable` with empty stdout.

**Read-only Git handling.** `command()` in `crates/loader-git/src/lib.rs` uses argv only, `env_clear()`, then sets `PATH=""`, `LC_ALL=C`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_LAZY_FETCH=1`, `GIT_NO_REPLACE_OBJECTS=1`, `GIT_OPTIONAL_LOCKS=0`, and passes `--no-pager --literal-pathspecs --no-replace-objects --no-optional-locks -c protocol.allow=never -c core.hooksPath=/dev/null -c core.fsmonitor=false`. Empty child `PATH` additionally denies helper lookup. `open()` refuses `extensions.partialclone`/`remote.*.promisor` before any object access and requires exit 1 with empty stdout *and* stderr to treat the probe as clean. Ownership refusal is classified as `UnsafeRepository` with guidance to use a caller-owned checkout — the loader never widens `safe.directory`, which is the conservative reading I asked for.

**Pinning and membership (ac-0001, ac-0008).** `list()` resolves the tip once through `rev-parse --verify --quiet --end-of-options`, requires it to be a commit, and builds `GitNoteRef`s carrying repository, common dir, ref, tip, target commit and blob. `read()` independently re-resolves the repository, requires canonical identity equality, re-verifies the tip type, re-verifies the blob's membership under the pinned tree via the same selective lookup, requires the target to be a commit, reads `cat-file -s` before `cat-file blob`, and rejects any length mismatch. The proof then rewrites the note with `notes add -f` and re-reads through the pinned reference, asserting byte-identical output, and separately forges a blob ID and asserts `invalid_data`. That is a genuine TOCTOU/moving-ref defence with a matching regression.

**Selective fanout (F7).** `selected()` walks two-hex levels with nonrecursive `ls-tree` and two literal pathspecs, treats any unexpected entry or duplicate match as `invalid_data`, and decrements a cumulative listing budget. The proof pins the behavioural difference rather than the implementation: with `--max-listing-bytes 180`, an `All` export fails `listing_limit` while the explicit `--commit` export succeeds and matches the SDK byte-for-byte.

**Parser fidelity (ac-0003, F5b/F5c).** Divider detection matches the reference reader's first-`---`-line semantics including `\r` handling; `file_path()` accepts unquoted paths and rejects unquoted whitespace, decoding quoted paths; `line_range()` accepts singletons and inclusive ranges, rejects zero and anything above `i64::MAX` (which is exactly the OTLP AnyValue bound), and per-entry ranges must strictly ascend; `legacy()` accepts 16-hex and the spec-line-193 7-hex keys; `attestation_key()` splits `s_<14hex>::t_<14hex>` and routes `h_` and legacy keys to their maps. `NoDuplicates` rejects duplicate JSON keys so native identity evidence cannot be silently overwritten — a hardening step nobody asked for and a good one. `string_field()` correctly treats optional fields as "if present and non-null, must be a string", so spec-legal notes without `git_ai_version` still parse.

**No synthesis (ac-0003, ac-0007).** `identity_attributes()` emits agent `tool`/`id`/`model` and the four declared counters only when present, preserving `null` versus missing, and gates `human_author`, `author`, `custom_attributes`, `messages` and `messages_url` behind `include_content`; attribution records deliberately pass `MappingOptions::default()` so content is retained once on the identity record and never copied per line range. No `timestamp_unix_nano`, no span or trace IDs, no zero-filled statistics anywhere — the opposite of the reference implementation's `total_additions: 0` shim. Unresolved keys emit the native key, prefix kind and range with `identity_resolution=unresolved` and no invented identity, and there is no cross-note or cache lookup.

**Contract-required attributes (F3).** `common()` emits `unisphere.profile.version` integer 1, `source.adapter`, `source.path`, `source.kind`, `source.key`, `source.revision`, `source.format=git_notes` plus `git.repository.id`, `git.notes.ref`, `git.notes.tip`, `git.commit`, `git.note.blob`. The SDK manifest carries the same common set with `notes_manifest`/`$git-notes`, null revision and tip for an absent ref, and the enumerated `unisphere.git_notes.*` fields including `ref_state` and `finality=unknown`. This satisfies the pre-existing non-JSONL branch of `crates/app/src/adapters.rs` (key + revision + format present, offset absent) without that assertion being weakened — I checked the diff of that test and only the fixture branch and the id set changed.

**Bounded amplification (explicit review focus).** `account_git_record()` sums event name, attribute keys and all nested string bytes, is called per record inside the adapter and again cumulatively across notes and the manifest in the SDK, and fails as `Output(OutputLimit)` before any destination write. Two regressions defend it: a unit test mapping a 64 KiB path across 600 ranges, and a proof case building a note with a 100k-escape path across 60 ranges, both asserting `UNI-LIMIT-OUTPUT` with empty stdout. Peak allocation is therefore bounded by that ceiling plus per-record map overhead, not by input size alone.

**Output safety.** `output_path()` canonicalizes the destination parent, rejoins the leaf, and rejects any path under the canonical common dir, per-worktree Git dir or worktree root using component-wise `starts_with`, then opens with `create_new(true)`, which also rejects existing files and symlinks. The residual concurrent-parent-replacement race is documented rather than claimed safe.

**Proof quality.** `parity()` byte-compares external SDK against temporarily-installed CLI output and hashes the entire source repository tree before and after every run, so "no source writes" is measured, not asserted. Other cases: hostile inherited `GIT_DIR`/`GIT_WORK_TREE`/`GIT_CONFIG_COUNT` promisor injection/`GIT_SSH_COMMAND` side-effect marker, asserted to produce output identical to the clean run; empty selection versus absent ref distinguished through `ref_state`; write and flush failures asserted as `UNI-WRITE` with no accepted collection; promisor config asserted as `unsupported_repository`; ownership refusal forced through `GIT_TEST_ASSUME_DIFFERENT_OWNER` in a wrapper the code comments explicitly confine to negatives; bare and linked worktree parity. `boot-attempt-1.json` records a genuine earlier clippy failure and is retained beside the passing attempt, which is the right evidence hygiene.

**Scope discipline.** No `refs/harness-telemetry` reader, segment/rollup import or migration path appears anywhere in the diff, and no discovery/query/filter/search surface was added — the CLI exposes only `list` and `export` over an explicitly selected repository and ref. `run_with_snapshot` gained an explicit rejection arm for `GitNotes` rather than a silent fallthrough. Documentation (`cli.md`, `telemetry-profile.md`, `fidelity.md`, `adapters.md`, `sdk.md`) was migrated coherently, including the `source.format` vocabulary and the new source kinds I flagged as a reminder at R2.

## Non-blocking observations

1. **Per-note repository re-resolution costs about eleven subprocesses per note.** `read()` calls `open()` for every note, and `open()` alone spawns the promisor-config probe plus four `rev-parse` invocations; adding the tip type check, the two-level selective lookup, the target type check, `cat-file -s` and `cat-file blob` gives roughly eleven child processes per note, so the default `max_notes: 1000` ceiling implies on the order of eleven thousand spawns. Everything stays bounded and correct, and the per-note membership, type and size re-verification is a real security property worth keeping. The avoidable part is repository resolution: `list_notes` could return a validated repository handle that `read_note` consumes, leaving the pinned-membership re-check intact. Worth a follow-up, not a fix before landing.
2. **Dubious-ownership classification depends on Git's English message prefix.** `command()` matches `stderr.starts_with(b"fatal: detected dubious ownership in repository")`, stabilised by `LC_ALL=C`. If upstream rewords that fatal, the failure degrades to `ObjectRead` — still typed and safe, but the actionable "use a caller-owned checkout" guidance is lost. Cheap hardening: also accept a match anywhere in the captured stderr, or note the coupling in a comment so a future Git bump is diagnosed quickly.
3. **stderr overflow reports `ListingLimit`.** `capture_pipe` is shared by both pipes with a 64 KiB stderr cap, so a diagnostic flood is reported as a listing-budget failure. Only reachable with a hostile or broken Git binary; a dedicated kind or a comment would make the intent obvious.
4. **`standard_git()` probes only `/usr/bin/git` and `/bin/git`.** Test-side only, and the failure message is explicit rather than a silent skip, but a host whose only Git is under `/opt/homebrew/bin` cannot run the fixture builder. Worth knowing before this proof runs in a different CI image.
5. **`AGENTS.md` was edited although it is outside tk-0004's approved owned paths.** The two-line change is accurate — it replaces the stale `configuration-and-claude-jsonl` scope string I flagged at R2 and updates the capability sentence — but the approved guide deliberately scoped ownership to seven harness/doc paths that did not include it. I would rather Main ratify this explicitly than have an out-of-scope edit pass unremarked; the content itself is correct and I would not want it reverted.
6. **Two error-envelope shapes now live under `command: "sessions"`.** JSONL adapters emit `error.code`/`fix`/`offset` from `session_error`, while git-ai emits `kind`/`message`/`output_code`. This is documented at `docs/cli.md:376-378` and both carry `kind`, so it is a disclosed divergence rather than a defect; a machine consumer switching adapters should be told to branch on `kind` rather than expect `code`.
