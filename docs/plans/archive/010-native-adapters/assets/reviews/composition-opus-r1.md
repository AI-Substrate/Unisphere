## Contract findings, now enforced in code

**C1 (snapshot provenance) is executable.** `proof/collection.rs` no longer demands `unisphere.source.offset` unconditionally. It selects the required set by representation — snapshots must carry `unisphere.source.key`, `.revision` and `.format`, JSONL must carry `.offset` — and it *rejects* any snapshot record that carries an offset at all ("snapshot invents a byte offset"). It also now asserts `unisphere.profile.version` has `intValue == "1"`, which retires my R2 residual D1: a string `"1"` would fail the proof, and every production emission I read (`json!(1)` in all seven adapters and in `sdk/snapshot.rs`) is the number.

**C3 (provenance ownership) is executable.** `app/src/adapters.rs` holds one private `AdapterRegistration` array of nine entries, each carrying a `SourceRepresentation`. `production_catalog_ids_match_exported_provenance` iterates every registration, materialises a representation-appropriate real fixture — including building an actual SQLite database for the `cursorDiskKV` entry — runs a real export, and asserts on *every emitted record* that `unisphere.source.adapter` equals `descriptor.id`, that JSONL sources carry an offset and that snapshot sources carry key/revision/format and no offset. `proof/native.rs` closes the same loop from outside: it compares the installed CLI's `adapters list --json` ID set against its own case list and fails on any difference, so a tenth registration cannot ship without proof coverage. The purity sensor was generalised the same way, enumerating every `unisphere-adapter-*` package from cargo metadata and erroring if a package's `src` yields no files.

This is the shape I asked for at R2 and it kept the property that mattered: coverage extends to the next registration automatically instead of requiring someone to remember. Note also that the representation lives in the private registry, not in `AdapterDescriptor` — so the `adapters list --json` wire shape is unchanged and my R2 secondary note is resolved by design rather than by a core edit.

**C4 (validation ownership) holds at both seams.** `FileSnapshotLoader::read_snapshot` validates source and limits before touching the filesystem, `unix::read_snapshot` calls `snapshot.validate(limits)` before returning, and `SnapshotCollector::collect_snapshot` independently re-validates the returned snapshot *and* rejects a loader that hands back a different `SnapshotRef` than was requested. An injected third-party `SnapshotLoader` therefore cannot smuggle an unbounded or substituted snapshot into a pure mapper.

**C5 (executable proof) is real.** Every check in the retained boot ran under PM, and the artifacts name themselves honestly.

## Composition, judged on behavior

**Three-way parity is genuine, not a stub.** `proof/native.rs` builds the in-tree CLI, `cargo install --debug`s a second copy to a temporary root, and compiles a *separate Cargo project* that depends on the crates by path and uses only `unisphere_sdk` public API. All three must produce byte-identical stdout for ten cases across both content policies, with the SDK's stderr empty. The JSONL side runs with `--max-records 1`, so multi-batch cursor iteration must reproduce the single-shot bytes exactly.

**Revision semantics are proven by mutation, not asserted.** A JSON document is exported, then a request is revised (revision must change, new value present, old `SENSITIVE-USER-TEXT` absent), then emptied (revision changes again, deleted request gone). A journal is exported, truncated mid-operation — exit 1 with **empty stdout**, proving no prefix publication — then completed, and the late append must appear with a new revision. A real SQLite database is seeded and then mutated late/update/delete through the external consumer; each mutation must change the revision, the update must not retain the stale value, and the delete must leave exactly one record: the closing manifest alone. That last case is the contract's "empty snapshots remain observable" clause demonstrated end to end.

**Checkpoint-after-output is proven with a real failing writer.** The consumer's `PartialThenFail` accepts 11 bytes and then returns `BrokenPipe`; the probe asserts `PipelineErrorKind::Write`, exactly 11 bytes landed, and no checkpoint returned, then retries successfully. The published claim is `checkpoint_on_failure: false, partial_bytes: 11` — an honest statement that bytes *can* reach a destination while no checkpoint is issued, which is precisely what `docs/fidelity.md` says. A deleted source likewise yields exit 1 and empty stdout.

**Storage safety is careful.** `SourceFile::open` uses `O_NOFOLLOW | O_NONBLOCK` and rejects non-regular files, closing both the leaf-symlink race and a FIFO stall. `verify` re-checks `symlink_metadata` and the live descriptor against `dev`/`ino` and, for JSON, an `(len, mtime, mtime_nsec, ctime, ctime_nsec)` stamp — the in-file test walks append, truncate, rewrite-with-restored-mtime, rename-replace, unlink and symlink-swap, and the rewrite case deliberately restores `mtime` to prove `ctime` carries the detection. SQLite deliberately skips the stamp with a stated reason (a committed WAL write does not invalidate a transaction snapshot) while keeping `dev`/`ino`.

The SQLite path is the strongest part of the delivery. It canonicalises only the caller-trusted parent and rejoins the filename so `SQLITE_OPEN_NOFOLLOW` still guards the leaf; it opens read-only with no URI interpretation and an explicit rejection of `immutable=1` on the grounds that it would discard live WAL updates; it disables trusted schema and views; it bounds `SQLITE_LIMIT_LENGTH`; it refuses non-UTF-8 database encodings rather than under-budgeting an implicit conversion; it verifies through `pragma_table_list` and `table_xinfo` that the target is an ordinary table with real, non-hidden `key`/`value` columns, excluding views, virtual and generated columns; it preflights sizes with `octet_length` on stored columns — with a comment explaining that `length(TEXT)` or a `CAST` would load the oversized value it is trying to avoid — and deliberately omits `ORDER BY` to avoid materialising an unbounded sorter, sorting in Rust instead so the revision digest stays deterministic. Duplicate keys are rejected after extraction. The table name reaching `format!` is constrained to `[A-Za-z0-9_]` by `SnapshotRef::validate` and quoted.

The revision digest is domain-separated (`unisphere.snapshot.v1\0`), includes the format and table, and length-prefixes every key and value, so two different key/value partitions cannot collide into one revision.

**Mappers are pure and honest.** Every adapter crate is `#![forbid(unsafe_code)]`, and the architecture sensor now restricts adapter dependencies to `unisphere-core`, `serde_json` and `time` — `rusqlite` is admissible only for `loader-snapshot` and, as a dev-dependency, for `app`. A mapper therefore cannot acquire a database handle, which is a structural guarantee, not a review promise.

Keys are native or documented-structural throughout: `document`, `journal:<ordinal>` from the loader, exact `cursorDiskKV` strings, and JSON-Pointer-style structural suffixes such as `document#/requests/0/message` from the mappers. The reduced VS Code journal is keyed `journal:reduced` rather than being attributed to any single physical line — the correct call, since the projection is a fold over all of them. The manifest's `$snapshot` sentinel is likewise clearly synthetic rather than a pretend native key.

The Cursor IDE mapper projects composer-declared bubble order, requires `_v >= 2`, cross-checks each bubble's `type` against its header entry, diagnoses orphan and duplicate bubble references as `UnsupportedRecord`/`InvalidField` instead of dropping them silently, tags token counts with an explicit `native_bubble_snapshot` scope so they cannot be read as operation totals, and refuses to dereference `images`, `attachedCodeChunks`, `contextPieces` or `allThinkingBlocks` — they raise `UnsupportedPart` and set `unisphere.content.omitted`. `unisphere.source.kind` carries each dialect's own native token, which for Cursor bubbles is the stringified numeric `type`. Mixing `"composerData"`, `"1"`, `"user"` and `"unknown"` in one attribute looks uneven, but it is the honest choice: inventing a name for Cursor's integer would be exactly the inference this profile forbids, and `unisphere.source.adapter` is always present to disambiguate.

It names the unavailable `composerHeaders` cross-table join, the opaque Cursor CLI BLOB codec, Pi v1/v2 migration and active-branch reconstruction, Copilot legacy coverage bounded by two-file structural evidence with model/usage/timestamps explicitly *not* inferred, historical versions of the unversioned journal envelope, producer-omitted LM tool parameters as a source limitation, and source-redacted content as a source limitation rather than a mapper gap. ## Findings

**K1 — journal hole budget is counted in JSON bytes but paid in `Value` elements (low, accepted).** `journal::reduce` bounds synthesized sparse-array nulls at `total_raw_bytes / 4` elements, which correctly prevents a tiny hostile `i` from requesting gigabytes. But the budget is a count of `serde_json::Value` slots, each costing `size_of::<Value>()` resident bytes, not four. With default limits a single crafted operation inside a 32 MiB record can legitimately claim roughly 8M null slots, so peak memory is a multiple of `max_snapshot_bytes` rather than comparable to it. Bounded and non-fatal, and the direction is right — but an operator sizing a collector from `max_snapshot_bytes` will under-predict RSS. My multiplier is arithmetic, not measurement; PM should measure before choosing between bounding holes against `max_records` and documenting the ratio in `docs/snapshot-loader.md`.

**K2 — `vscode-copilot` publishes two storage formats but its registration defaults to one (low, accepted).** `DESCRIPTOR` advertises four location hints, two with `storage_format: "json_document"` and two with `"json_journal"`, while the registry pins `SourceRepresentation::JsonDocument`. Exporting a real `*.jsonl` journal therefore requires the operator to add `--source-format json-journal`; without it the journal is parsed as a single document and fails `InvalidData`. It fails closed, never mismaps, and `proof/native.rs` covers the journal path explicitly — so this is a discoverability cliff, not a correctness hole. It is also nearly free to close, because the machine-readable answer is already published: the CLI could derive the format from the matched hint's `storage_format` instead of requiring the operator to restate it.

**K3 — the nested `checks` scope string still says Claude-only (low, accepted).** In the retained boot, `data.scope` is `configuration-and-native-session-projections` while `data.checks.data.scope` is `configuration-and-claude-jsonl`. The quality lane under-claims what it now gates — six adapters, the snapshot loader and the extended architecture and purity sensors all run inside it. Under-claiming is the safe direction and nothing depends on the string, but a reader citing `harness checks` alone would understate delivered coverage. Harness-owned, adjacent to rows 54/55, not product source.

## Basis and boundaries

The question for a composition round is whether independently built units compose into one honest product. They do: nine registrations behind one dispatcher, three binaries producing identical bytes, revision and replacement semantics demonstrated against real mutating sources, refusal proven where refusal is correct, and provenance vocabulary enforced by a proof that now distinguishes representations instead of demanding a byte offset from a database row.

What this does not establish: that any dialect's *interpretation* matches what the vendor application means, since every fixture is synthetic and bounded by retained structural evidence; that anything works off this Unix host, on Windows, or against a live installation; that the loader is safe against a hostile *ancestor directory*, which remains caller-trusted by documented design; or that the formal Builder chain is satisfied — it is not, and the artifacts say so. I ran nothing; every runtime outcome cited here is PM's retained evidence, read and reconciled, not reproduced.
